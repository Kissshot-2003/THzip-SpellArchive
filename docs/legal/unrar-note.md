# RAR 支持的法务边界

## 现状

`thzip-core` 依赖 `unrar-ng`（及其 `unrar-ng-sys`），二者把 UnRAR 的 C++ 源码
编进二进制。RAR 解压是产品的重要能力，RAR 不在设计文档 v0.1 的核心范围内
（原计划 v0.3 可选），实际已做成核心只读格式。

## 需要注意的点

1. **UnRAR 许可不是 OSI 许可。** 它允许免费使用与分发（含商业用途），但禁止
   使用其源码反向工程 RAR 压缩算法（例如拿它做出一个 RAR 压缩器）。
   `unrar-ng-sys` 的 `license` 字段声明为 `MIT OR Apache-2.0`，
   `cargo deny` 只能看到声明值，**看不到捆绑的 UnRAR 源码**。
2. **再分发义务。** 二进制分发时需要随包附带 UnRAR 许可声明。当前便携包与安装包
   都没有附带 —— 属于待补项，不是「已合规」。
3. **只读边界。** 项目只做 RAR 解压、不做 RAR 创建，这与 UnRAR 许可的限制方向一致。

## 决策记录

暂维持「RAR 只读 + 捆绑 unrar-ng」，理由是用户明确需要 RAR 支持，且只读用法
不触碰 UnRAR 许可的核心限制。此项需在正式对外发布前由法务确认。
